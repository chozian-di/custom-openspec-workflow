# Proposal

## Why

The installer stores the persistent Python package under
`~/.local/share/custom-openspec-workflow`. The generated helpers start Python
without setting `PYTHONPYCACHEPREFIX`, so Python creates `__pycache__` files
inside that persistent package directory.

The project is not released or installed for users. This is the right time to
separate persistent package files from generated Python bytecode.

## What Changes

- Add `~/.cache/custom-openspec-workflow` as the default Python bytecode cache
  root.
- Make installed wrappers set `PYTHONPYCACHEPREFIX` before Python starts.
- Make the repository shell launchers use the same cache default.
- Preserve an existing `PYTHONPYCACHEPREFIX` value as a user override.
- Keep the installed package and ownership manifest under
  `~/.local/share/custom-openspec-workflow`.
- Keep generated bytecode outside the ownership manifest and uninstall scope.
- Add path, wrapper, and disposable runtime tests.
- Document the separate package and cache locations.
- Do not add migration or cleanup behavior for old package-local bytecode.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `user-level-openspec-policy`: Define the default location and launcher
  behavior for generated Python bytecode in the user-level installation.

## Impact

The change affects `src/custom_openspec_workflow/paths.py`,
`src/custom_openspec_workflow/install.py`, the repository shell launchers,
`tests/test_paths.py`, `tests/test_install.py`, the user-level policy
specification, and `README.md`.

It does not add a dependency, change the persistent package location, change
the command names, or change the OpenSpec schema. The Python bytecode prefix
also applies to Python modules imported by these helpers, including their
runtime dependencies.
